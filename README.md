# OpenMetadata Learning Lab

OpenMetadata에서 지표의 정의·소유자·원천과 데이터 간 관계를 살펴보는 합성 메타데이터 실험입니다.
OpenMetadata 자체를 만든 프로젝트가 아니라, 기존 제품 위에 합성 자료를 등록하고 저장 결과를 대조하는 Python 도구입니다.

## 실험 장면

주문·환불 → 집계 파이프라인 → 일별 순매출 → 대시보드와 지표의 관계를 등록합니다.
합성 예시는 총매출 100에서 환불 30을 뺀 순매출 70입니다. 이는 실험의 계산 예시이며 일반 회계 규칙이 아닙니다.

등록된 다섯 관계는 실험을 위해 작성한 자료입니다. 제품이 실제 시스템에서 자동 발견한 관계가 아니며,
등록되지 않은 관계를 "영향 없음"으로 해석하지 않습니다.

## 서버 없이 실행하기

Python 3 표준 라이브러리만 사용합니다.

```bash
python3 compose/seed/seed_first_scene.py      # 요청 없이 계획만 출력
python3 compose/seed/test_verify_stub.py     # 가짜 API를 사용하는 검사
```

| 파일 | 역할 |
|---|---|
| `seed_first_scene.py` | 합성 자료 등록과 저장 재조회 |
| `expected-graph.json` | 개체·관계·계산 기대값 |
| `edge-context.json` | 관계의 의미와 확인 범위 |
| `test_verify_stub.py` | 누락·다른 소유자·응답 모양 등의 검사 |

## 구현과 확인 범위

[OpenMetadata 2.0.1](https://github.com/open-metadata/OpenMetadata/tree/bf621b166ec12e8c99fcb1c1443442723386fa41)을 대상으로
AI와 소스를 살펴보고 fixture와 검사를 작성했습니다. 개발 환경에서는 합성 개체·관계의 저장 재조회와 화면 탐색을 확인했습니다.
공개 사본에서 확인한 것은 dry-run과 14개 stub 시나리오입니다. 새 서버 전체 복원이나 실제 기업 데이터·권한·영향 범위는 검증하지 않았습니다.

서버·컨테이너·업스트림 화면 코드·실행 중 자료는 이 저장소에 포함하지 않습니다.
실제 서버 연결은 별도로 준비한 실험 인스턴스에서만 사용해야 합니다. `--verify-only`는 로그인과 조회를,
`--apply`는 생성을 포함한 **기존 자료 갱신**을 수행할 수 있습니다. 기본 명령은 쓰지 않습니다.

자체 클라이언트·fixture·검사에는 별도 공개 라이선스를 부여하지 않았습니다.
업스트림 제품과 실험 코드의 구현 주체는 구분합니다.
